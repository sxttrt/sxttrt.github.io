Painting Robot System Based on the Kinova Gen3-lite Robotic Arm

A comprehensive development log of a painting robot system, encompassing image scanning, path planning, and force-controlled trajectory tracking to achieve full automation from image input to physical execution.

I. Project Core Information

Category Details
Project Title Construction of a Painting Robot System Based on the Kinova Gen3-lite Arm
Core Members Yukun Li, Chengtao Liu, Bobin Wang
Timeline March 2025 - June 2025
Core Tasks 1. Image Scanning: Camera acquisition, preprocessing, edge detection, and contour extraction using OpenCV.
2. Trajectory Planning: Binarization, skeletonization, path merging/simplification, and coordinate normalization.
3. Robot Control: Force-controlled trajectory tracking under the ROS framework, coordinate transformation, and pen up/down simulation.
Key Tools Python, OpenCV (Image Processing), NumPy, ROS (Robot Operating System), Kinova Gen3-lite Arm, Kortex SDK, skimage (Skeletonization).

II. Background and Objectives

1. Project Background

Traditional manual painting relies heavily on experience and is prone to errors when replicating complex line drawings, with extremely low efficiency for batch reproduction. The Kinova Gen3-lite, a lightweight collaborative robot arm, offers a repeatability of ±0.1mm. By integrating computer vision with robotic control, it is possible to achieve a fully automated “Visual Perception → Path Planning → Mechanical Execution” closed-loop system.

This project targets lightweight scenarios such as educational demonstrations and creative workshops. By avoiding complex industrial-grade vision calibration and expensive force-sensing hardware, we utilize an open-source toolchain (OpenCV + ROS) to implement a low-cost, easy-to-deploy system. The core focus is on solving two challenges: “How to transform images into executable robot trajectories” and “How to maintain stable pen-to-paper contact without a dedicated force sensor.”

2. Core Objectives

  • Image Processing: Achieve precise contour extraction for line drawings (e.g., animal sketches, geometric patterns) under varying lighting, while filtering out paper textures and noise.
  • Path Planning: Convert contours into continuous, non-redundant trajectories with pen up/down markers to ensure smooth execution and minimize idle motion.
  • Robot Control: Implement end-effector force estimation based on the Jacobian Transpose method. Use a PD controller to maintain a stable 13N contact force across different paper thicknesses.
  • System Integration: Complete the full automation pipeline, aiming for an execution time of ≤ 5 minutes for sketches with up to 200 path points.

III. Key Task Implementation

Task 1: Image Scanning and Preprocessing (OpenCV)

1. Processing Workflow

  1. Hardware Initialization:
    • Utilized an industrial camera via cv2.VideoCapture(6) with a 480×640 resolution to balance processing efficiency and detail.
    • Calibrated brightness via cap.set(10, 160) to adapt to indoor lighting environments.
  2. Image Optimization:
    • Grayscale Conversion: Reduced computational load by focusing on contour features.
    • Gaussian Blurring: Used a 5×5 kernel to smooth the image and suppress salt-and-pepper noise.
    • Canny Edge Detection: Dynamically adjusted thresholds via a GUI trackbar to extract clear contours.
    • Morphological Enhancement: Applied dilation (5×5 kernel) to connect broken edges, followed by erosion to eliminate small-area noise.
  3. Contour Extraction:
    • Employed cv2.findContours with RETR_EXTERNAL to extract only outer boundaries and CHAIN_APPROX_SIMPLE to compress redundant points.

Task 2: Trajectory Planning (Image to Mechanical Path)

1. Implementation Steps

  1. Skeletonization: Used skimage.morphology.skeletonize to refine wide lines into single-pixel centerlines, significantly reducing trajectory complexity.
  2. Breakpoint Repair: Scanned the skeletonized image to detect and fill symmetric gaps (8-neighbor pixels), ensuring path continuity.
  3. Path Optimization:
    • Trajectory Tracking: Traversed pixels from identified endpoints to extract complete paths.
    • Path Merging: Merged endpoints within a 10-pixel Euclidean distance to minimize “pen-up” actions.
    • Simplification: Used cv2.approxPolyDP (epsilon=2 pixels) to retain key turning points while discarding redundant segments, reducing total points by over 60%.
  4. Coordinate Normalization: Mapped pixel coordinates (x, y) to a [0, 1] range to eliminate image size effects and adapt to the robot’s 0.5m×0.5m workspace.

Task 3: Robot Control (ROS & Kortex SDK)

1. Force Control Implementation

  1. End-effector Force Estimation (Sensorless):
    • Principle: Leveraged the robot’s Jacobian Transpose relationship to estimate end-effector forces from joint torque measurements. Formula: $$F_{ee} = J^T \tau$$ Where $F_{ee} \in \mathbb{R}^6$ is the estimated force/torque, $J \in \mathbb{R}^{6 \times 6}$ is the Jacobian matrix of the Gen3-lite, and $\tau \in \mathbb{R}^6$ is the measured joint torque.
  2. PD Force-controlled Trajectory Tracking:
    • Objective: Maintain a stable 13N contact force in the Z-axis.
    • Control Law: $$\Delta z = K_p e_f + K_d \dot{e}f$$ Where $e_f = F{desired} - F_z$ (force error), $K_p=0.005$, and $K_d=0.001$.
    • Robustness: Only activated the controller when $|F_z| > 1N$ to prevent oscillation in free space.

2. ROS Node Architecture

  • Jacobian Node: Subscribes to joint states to calculate and publish the Jacobian matrix and force estimates.
  • Painting Control Node: Subscribes to force feedback, parses path files, and publishes Cartesian motion commands.

3. Core Conclusions

Technical Aspect Key Findings
Preprocessing Gaussian blurring (5×5) + Dilation/Erosion removed over 90% of noise; edge extraction accuracy reached ≥95%.
Path Planning The workflow reduced path points by 60%-70%, increasing execution efficiency by over 50%.
Force Control Sensorless estimation kept contact force fluctuations within ±1.5N, meeting stability requirements.
Overall System Sketches with <200 points were completed in 3-5 minutes with a replication deviation of ≤1mm.
