A comprehensive record of the four-wheel car experimental modeling project, featuring open-loop system construction, second-order transfer function identification, Simulink simulation, and Arduino PID closed-loop deployment.

II. Background and Objectives

1. Project Background

Following the requirements for the four-wheel car experimental modeling course, this project utilizes a laboratory four-wheel vehicle (equipped with 2 brushed DC motors) as the research object. By implementing an experimental modeling workflow—“Data Acquisition → Model Generation → Simulation Verification → Hardware Control”—we aimed to deepen the practical application of PID control theory and system identification technologies. This project effectively addresses common issues in motion control, such as low precision and significant response latency.

2. Core Objectives

  • Construct an Arduino-based open-loop control system to achieve precise motor speed control via PWM commands.
  • Establish an open-loop model for linear motion using the MATLAB System Identification Toolbox, ensuring high model fit accuracy.
  • Perform open-loop simulation and offline PID tuning in Simulink, followed by hardware deployment on Arduino to achieve robust closed-loop control.

III. Core Task Implementation

Task 1: Open-loop System Construction and Model Identification

1. Open-loop Control System Setup

  • Hardware Foundation: Per the course requirements, a 4-motor vehicle was originally planned; however, due to hardware compatibility, an “Arduino two-wheel car” from the Smart Sensing project was used. Both platforms share identical functionality, utilizing encoders for real-time wheel speed acquisition.
  • Control Logic: Developed open-loop Arduino code defining motor pins (e.g., Motor_AIN1=6, Motor_AIN2=3) and encoder pins (ENCODER_A=2). Utilized 10ms timer interrupts to update speed counts. Real-time speed feedback was captured via a serial debugger while sending varying PWM values (100, 150, 250, 255).
  • Key Visuals:

    Fig 1: Left and right wheel test data

2. Experimental Model Identification

  • Data Preprocessing: Organized test data for 4 sets of PWM values (255, 250, 150, 100) into Excel. After removing outliers, the “PWM Input - RPM Output” dataset was imported into MATLAB.
  • Modeling Process: Employed the Step Response Method within the MATLAB System Identification Toolbox. Selected a second-order transfer function as the base model and fused 8 sets of valid data (4 PWM sets × 2 wheels) for fitting.
  • Accuracy Verification: Achieved an average model fit of 85.55%, with individual dataset fits ranging from 76.24% to 92.52%, satisfying the project’s precision requirements.
  • Key Visuals:

    Fig 2: Parameter identification via integrated datasets

    Fig 3: Identified transfer function and corresponding fit percentages

3. Simulink Open-loop Simulation Verification

  • Simulation Modeling: Built an open-loop model in Simulink featuring “Step Input (PWM=175 corresponding to 37 RPM)”, “Transfer Fcn”, and “Scope” modules.
  • Validation: Simulation fit across three iterations reached 91.83%, 92.58%, and 92.83%. The high overlap between simulation curves and physical measurements verified the model’s predictive accuracy.
  • Key Visuals:

    Fig 4: Open-loop Simulink model architecture

    Fig 5: Comparison between 175 PWM simulation and actual measured data

4. PID Closed-loop Control Tuning

  • Closed-loop Modeling: Integrated a “PID Controller” module into the open-loop architecture. Set an output limit of 45 (max motor RPM) to prevent system overload.
  • Parameter Optimization: Used the Simulink PID Tuner to achieve rapid response and minimal overshoot. Obtained parameters: P=1.117, I=13.04, D=-0.003613. Due to the negligible D value, the system was simplified to PI control for hardware deployment.

Task 2: PID Deployment and Physical Testing

1. Parameter Transformation and Implementation

  • Conversion: Based on the linear fit between PWM and RPM (coefficient 6.4677, offset -37.1855), the Simulink-optimized parameters were converted to Arduino-applicable values: KP=7.04, KI=0.8.
  • PI Control Code: Implemented an Incremental PI Control function. The logic involves calculating speed error (Target - Actual), accumulating the integral term, and limiting PWM output to drive the motors via 10ms timer interrupts.
  • Key Visuals:

    Fig 8: Linear fitting of PWM and target speed

    Fig 9: Snippet of incremental PI control implementation

2. Physical Validation

  • Testing Methodology: Selected three target speeds (37, 31, 21 RPM) to compare “Open-loop Control” vs. “PI Closed-loop Control” responses. Additionally, compared Simulink simulation results with actual hardware performance.
  • Core Conclusion: Closed-loop control significantly improved response time and reduced steady-state error compared to open-loop. The small discrepancy between simulation and measurement validated the high precision and practicality of the modeling approach.
  • Key Visuals:

    Fig 10: Performance comparison: Open-loop vs. Closed-loop at 37 RPM

    Fig 11: Comparison between simulation and hardware measurements at 37 RPM

IV. Project Results and Conclusion

This project strictly followed the “Open-loop Construction → Model Identification → Simulation Tuning → Hardware Deployment” workflow. Key outcomes include:

  1. Mathematical Description: Developed a second-order transfer function model with an average fit of 85.55% for precise motion characterization.
  2. Simulation Optimization: Designed a Simulink closed-loop scheme to optimize PID parameters (simplified to PI: KP=7.04, KI=0.8).
  3. Hardware Performance: The deployed Arduino PI controller demonstrated significant improvements in response speed and a marked reduction in steady-state error. Minimal errors between simulation and measurement further verified the modeling accuracy and practical utility of the controller.
