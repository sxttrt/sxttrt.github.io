Gomoku Recognition and Prediction System Based on Traditional Image Processing

A comprehensive Gomoku recognition and prediction system featuring Gaussian filtering, Canny edge detection, Hough transform, HSV-based piece classification, heuristic move prediction, and UI development (compatible with standard and hand-drawn boards).

II. Background and Objectives

1. Project Background

Automated recognition of Gomoku (Five-in-a-Row) is a classic application of computer vision. Traditional methods offer advantages such as controllable processes, low computational requirements, and straightforward implementation, making them ideal for lightweight recognition needs. This project moves away from “black-box” deep learning models, utilizing techniques like Gaussian filtering, Canny edge detection, and Hough transform to solve two core challenges: high-precision recognition of standard boards and robust recognition of hand-drawn boards. Combined with heuristic pattern analysis, the system achieves a full “Recognition - Modeling - Prediction - Interaction” closed-loop.

2. Core Objectives

  • Recognition: Achieve a 100% recognition rate for standard boards and ≥85% for neat hand-drawn boards, with precise classification of black and white pieces.
  • Modeling: Construct a 15×15 board state model and implement normalized coordinate mapping to ensure data alignment with the physical board.
  • Intelligence: Develop a move prediction algorithm based on pattern scoring and implement real-time win/loss judgment (5-in-a-row detection in horizontal, vertical, and diagonal directions).
  • Interaction: Design a UI compatible with multiple board formats, supporting image importing, result visualization, and user interaction.

III. Core Task Implementation

Task 1: Standard Board Recognition and Piece Classification

1. Methodology

Adopted a four-step pipeline: “Preprocessing → Piece Detection → Color Classification → Coordinate Mapping.”

  • Preprocessing: Input images are denoised via Gaussian filtering (5×5 kernel) and converted to grayscale to reduce complexity.
  • Piece Detection: Used cv2.HoughCircles (Hough Circle Transform) with a radius range of 10-18px and a minimum distance of 25px to extract precise centers of the pieces.
  • Color Classification: Transformed the Region of Interest (ROI) from RGB to HSV color space. Pieces were classified using thresholds: White (Value > 120) and Black (Hue < 90).
  • Coordinate Mapping: Calculated grid sizes based on board dimensions to map centers into 15×15 row/column indices.

2. Key Results

  • Standard Board Performance: Achieved nearly 100% recognition rate with zero deviation in coordinates or color classification.

Task 2: Hand-drawn Board Recognition and State Modeling

1. Methodology

Designed a robust four-step workflow to handle irregular edges and piece adhesion:

  • Board Localization: Extracted the largest contour via cv2.findContours and used a bounding box to crop the board, resizing it to a fixed 1000×1000px.
  • Edge Detection: Applied the Canny operator (thresholds 50-150) followed by dilation (5×5 kernel) to enhance line continuity and separate grid boundaries.
  • Grid Sorting: Sorted extracted grid rectangles based on “diagonal distance (x+y)” to generate a 15×15 matrix, ensuring alignment with the physical grid.
  • Piece Judgment: Calculated the ratio of white pixels within each grid and used the “Area-to-Perimeter ratio” (Circle < 1.3, Cross > 1.3) to distinguish between empty, black, and white (cross-marked) cells.

2. Key Results

  • Hand-drawn Performance: Achieved ≥85% accuracy for neat hand-drawn boards. Morphological operations effectively mitigated issues with boundary adhesion or line breaks.

Task 3: Move Prediction and Win/Loss Judgment

1. Move Prediction Implementation

The move prediction is the core intelligence of the system, utilizing a three-tier architecture: “Pattern Scanning - Score Calculation - Optimal Decision.”

(1) Pattern Recognition: Double-pointer Interval Scanning
  • Logic: Scanned four directions (Horizontal, Vertical, Main Diagonal, Anti-diagonal) using a sliding window (lengths 5 to 11). This ensures complex patterns like “Live 3 + Live 4” are captured without omission.
  • Filtering: Implemented specific rules to avoid redundant counting of overlapping patterns and utilized edge-case logic for patterns near the board boundaries.
(2) Score Calculation: Pattern Weights and Bonus Points
  • Base Scores: Predefined weights for typical patterns (e.g., Live 4: 1000, Dead 4: 500, Live 3: 300).
  • Bonus Mechanism: Added additional scores for lethal combinations (e.g., +30 for “Live 4 + Live 3”) to prioritize aggressive winning moves.
(3) Optimal Decision Strategy: Attack-Defense Balancing
  • Search Optimization: Focused searches within a ±2 grid range of existing pieces to improve efficiency.
  • Decision Formula: Calculated the “Yield Difference” for each empty cell to balance offensive gains and defensive requirements: Yield = 1.1 × (Post-move Black Score - Pre-move Black Score) + (Pre-move White Score - Post-move White Score)
  • Kill Move Priority: If any move results in an immediate Win/Live 4 (Score ≥ 1000), it is selected instantly.

2. Win/Loss Judgment

  • Full-direction Detection: Constructed 29 diagonal detection arrays to ensure comprehensive coverage.
  • Victory Interaction: Upon detecting a 5-in-a-row string (“XXXXX” or “OOOOO”), the UI displays a victory pop-up and automatically resets the board after a 3-second delay.

Task 4: UI Development

1. Features

Developed an interactive Tkinter interface supporting:

  • Image Import: Upload standard or hand-drawn board images (JPG/PNG).
  • Visualization: Toggle between “Original,” “Grayscale,” and “Recognized” views.
  • Interaction: Supports manual moves and real-time next-move prediction (indicated by colored masks: Red for Black, Green for White).

IV. Project Results Summary

  • Recognition Precision: ~100% for standard boards, ≥85% for neat hand-drawn boards, and ≥98% for color classification.
  • System Performance: Prediction latency ≤0.5s; move recommendations align with standard Gomoku strategies (prioritizing Live 4/Live 3 patterns).
  • Compatibility: Seamlessly supports 15×15 standard boards and dynamically resizes hand-drawn inputs.
